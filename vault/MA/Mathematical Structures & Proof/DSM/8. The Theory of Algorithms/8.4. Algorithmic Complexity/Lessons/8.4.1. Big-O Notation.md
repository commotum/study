## Introduction

An **algorithm** is a step-by-step set of instructions or rules designed to perform a specific task or solve a particular problem. It is like a recipe that tells a person or computer precisely what to do in a methodical, structured way. However, not all algorithms are equally efficient because some take longer than others to solve the same problem.

Suppose, for example, we wish to write an algorithm for computing the sum of the squares $S(n)$ of the first $(n+1)$ natural numbers. One way to do this is to compute the sum using a so-called **brute force approach**, which involves explicitly calculating and summing each squared term:

$$
S(n) = 1^2+2^2+3^2+\cdots + n^2 + (n+1)^2
$$

Let's analyze how many arithmetic operations it takes to compute this sum:

- For $n=1$, we require a total of $3$ arithmetic operations to compute the sum (two products and one summation):
$S(2) = 1\cdot 1 + 2\cdot 2$
- For $n=2$, we require a total of $5$ arithmetic operations to compute the sum (three products and two summations):
$S(3) = 1\cdot 1 + 2\cdot 2 + 3\cdot 3$
- For $n=3$, we require a total of $7$ arithmetic operations to compute the sum (four products and three summations):
$S(3) = 1\cdot 1 + 2\cdot 2 + 3\cdot 3 + 4\cdot 4$

Observing the pattern, we see that for a given $n$, the number of arithmetic operations is given by the function

$$
f_1(n) = 2n+1
$$

Since this grows linearly with $n$, the brute force method becomes inefficient and impractical for large $n$.

The second method uses the well-known sum of squares formula

$$
S(n) = \sum_{i=1}^{n+1} i^2 = \dfrac16 (n+1) (n+2)(2n+3)
$$

Writing each arithmetic operation on the right-hand side explicitly, we have

$$
S(n) = \sum_{i=1}^{n+1} i^2 = (1 / 6) \cdot (n+1) \cdot (n+2)\cdot (2\cdot n+3)
$$

This method requires only $8$ arithmetic operations (one division, four products, and three summations). Thus, the number of arithmetic operations for this algorithm is given by

$$
f_2(n) = 8
$$

Notice that $f_2$ is independent of $n$, which means the second algorithm is much more efficient than the first.

Both algorithms produce the same result, but the second requires far fewer operations for large $n$. If we were to write some code for these algorithms on a computer, the second would execute faster for large $n$, and the difference becomes even more significant as $n$ grows.

This example shows why it is important to compare algorithms' performance. The field of **algorithmic complexity** studies how fast or slow algorithms run as their input size grows. It helps us compare different algorithms to see which one is more efficient.

To do this, we need a mathematical way to describe how their efficiency scales with $n$. That's what we'll discuss next.

<a id="defining-the-set-on"></a>
## Defining the Set O(n)

To compare algorithms, we need a systematic way of describing how a function behaves as its input $n$ grows.

Recall that, for the brute force solution to our sum-of-squares problem, the total number of arithmetic operations was given by

$$
f_1(n) = 2n+1
$$

Our goal is to describe this function's behavior using an **asymptotic upper-bound**:

- *Asymptotic* means we're interested in $n\to\infty$.
- Finding an *upper bound* means we'd like to find a positive constant $c$ and a positive function $g(n)$ such that $f_1 \leq c g$ for $n\to\infty$.

We can form an asymptotic upper bound for $f_1$ by observing that it is bounded above by $3n$ *for all*

$$
n\geq n_0 = 1
$$

as shown below.

![](<../Source/8.4.1. Big-O Notation/Images/757207cf730d78613b88613ada3f56df.png>)

Thus, for all

$$
n\geq n_0
$$

we have

$$
2n+1 \leq c g(n)
$$

where

$$
g(n) = n, \qquad c = 3, \qquad n_0 = 1
$$

There's nothing special about our choice of constants $c$ and $n_0$ here. We could have also selected $c=4$ and $n_0=2$, for example.

We define the set of functions that are **of the order $\boldsymbol n$**, denoted $O(n)$, as follows:

$$
O(n) = \big\{f(n) \:: \: \exists c, n_0 > 0, \: \forall n \geq n_0, \: 0 \leq f(n) \leq c n \big\}
$$

In plain English, the set $O(n)$ describes all nonnegative functions bounded above by some positive linear function $cn$ for sufficiently large $n$. This notation is often called **big-O** (pronounced "big-oh") notation.

We say that

$$
f_1 = 2n+1
$$

is **of the order** $\boldsymbol{n}$, and we write $f_1\in O(n)$.

<a id="defining-the-set-o1"></a>
## Defining the Set O(1)

Let's return to the solution to our sum-of-squares problem using the sum-of-squares formula. Recall that the total number of arithmetic operations was given by

$$
f_2(n) = 8
$$

Thus, for all

$$
n\geq n_0
$$

we have

$$
8 \leq c g(n)
$$

where

$$
g(n) = 1, \qquad c = 8, \qquad n_0 = 1
$$

Again, there's nothing special about our choice of constants $c$ and $n_0$ here. We could have also selected $c=100$ and $n_0=50$, for example.

We define the set of functions that are **of the order $1$**, denoted $O(1)$, as follows:

$$
O(1) = \big\{f(n) \:: \: \exists c, n_0 > 0, \: \forall n \geq n_0, \: 0 \leq f(n) \leq c \big\}
$$

In plain English, the set $O(1)$ describes all nonnegative functions bounded above by some positive constant for sufficiently large $n$.

We say that

$$
f_2 = 8
$$

is **of the order** $\boldsymbol{1}$, and we write $f_2\in O(1)$.

---

<a id="defining-the-set-ogn"></a>
## Defining the Set O(g(n))

We can generalize these concepts by defining the set $O(g(n))$ as follows:

$$
O(g(n)) = \big\{f(n) \:: \: \exists c, n_0 > 0, \: \forall n \geq n_0, \: 0 \leq f(n) \leq c g(n) \big\}
$$

This is the set of all nonnegative functions $f(n)$ such that, for each $f$, there exist positive constants $c$ and $n_0$ such that for all $n$ larger than $n_0$, the values of $f(n)$ are not larger than $c \cdot g(n)$.

Geometrically, this means that starting from a certain point $n=n_0$, the graph of

$$
y=c \cdot g(n)
$$

lies *above* the graph of $y=f(n)$ for all

$$
n\geq n_0
$$

![](<../Source/8.4.1. Big-O Notation/Images/c8c8ba7bc85fad672d280e8f3a15736d.png>)

For example, the set $O(4^n)$ is defined as follows:

$$
O(4^n) = \big\{f(n) \:: \: \exists c, n_0 > 0, \: \forall n \geq n_0, \: 0 \leq f(n) \leq c \cdot 4^n \big\}
$$

In the context of algorithmic complexity, the functions $f$ and $g$ in our definition are always nonnegative since any algorithm requires zero or more steps to run.

Let's see some more examples.

$$

<a id="proving-that-a-function-belongs-to-a-big-o-set"></a>
## Proving That a Function Belongs to a Big-O Set

**Example:** Prove that $8n - 2 \in O(n^2)$ for $n\in\mathbb N$.

**Explanation**

According to the definition, $O(g(n))$ is the set of all functions $f(n)$ for which there exist positive constants $c$ and $n_0$ such that for all $n$ larger than $n_0$, the values of $f(n)$ are not larger than $c \cdot g(n){:}$

$$
O(g(n)) = \big\{f(n) \:: \: \exists c, n_0 > 0, \: \forall n \geq n_0, \: 0 \leq f(n) \leq c g(n) \big\}
$$

So, we start as shown below.

> We need to show that there exists a constant $c$ such that for sufficiently large $n$, we have
> $8n - 2\leq c n^2$.

Now, let's isolate $c$ on the right-hand side of the inequality.

> Dividing both sides of the inequality by $n^2$, we get the following:
> $\begin{bmatrix}8n - 2 & \le cn^{2} \\ \frac{8n - 2}{n^{2}} & \le \frac{cn^{2}}{n^{2}} \\ \frac{8n}{n^{2}} - \frac{2}{n^{2}} & \le \frac{cn^{2}}{n^{2}} \\ \frac{8}{n} - \frac{2}{n^{2}} & \le c\end{bmatrix}$

Notice that

$$
\dfrac{8}{n} = 8
$$

and

$$
\dfrac{2}{n^2} = 2
$$

if $n=1$. Also, both

$$
\dfrac{8}{n}
$$

and

$$
\dfrac{2}{n^2}
$$

monotonically approach $0$ as $n \to \infty$. As a result,

$$
\dfrac{8}{n} - \dfrac{2}{n^2} \leq 8
$$

for all

$$
n \geq 1
$$

and we can now pick our constants.

> By setting $n_0=1$ and $c=8$, we make the above inequality hold for any $n \geq n_0$.

Of course, other choices for the constants $c$ and $n_0$ may do the job, but the important thing is we found at least one such combination.

> Therefore, $8n - 2 \in O(n^2)$.

The full proof is shown below:

> We need to show that there exists a constant $c$ such that for sufficiently large $n$, we have
> $8n - 2\leq c n^2$.
> Dividing both sides of the inequality by $n^2$, we get the following:
> $\begin{bmatrix}8n - 2 & \le cn^{2} \\ \frac{8n - 2}{n^{2}} & \le \frac{cn^{2}}{n^{2}} \\ \frac{8n}{n^{2}} - \frac{2}{n^{2}} & \le \frac{cn^{2}}{n^{2}} \\ \frac{8}{n} - \frac{2}{n^{2}} & \le c\end{bmatrix}$
> By setting $n_0=1$ and $c=8$, we make the above inequality hold for any $n \geq n_0$.
> Therefore, $8n - 2 \in O(n^2)$.

<a id="properties-of-big-o-notation"></a>
## Properties of Big-O Notation

Let's recall our two algorithms for computing the sum of squares of the first $(n+1)$ integers:

- The brute force approach:
$S(n) = 1^2+2^2+\cdots + n^2+(n+1)^2$
This algorithm requires $f_1 = 2n+1$ arithmetic operations to compute, thus $f_1 \in O(n)$.
- The sum-of-squares formula:
$S(n) = \dfrac16 (n+1)(n+2)(2n+3)$
This algorithm requires $f_2 = 8$ arithmetic operations to compute, thus $f_2 \in O(1)$.

Geometrically, $f_2\in O(g(n))$ if $f_2$ is bounded above by $c g(n)$ for sufficiently large $n$. However, while $f_2\in O(1)$, it's clear that some function of the form $cn$ *also* bounds $f_2$ for sufficiently large $n$. Therefore, we have that
$f_2 \in O(n)$.
Following this line of reasoning for any $f\in O(1)$, we see that
$O(1) \subset O(n)$.

Similarly, any $f\in O(n)$ is also bounded above by some function $cn^2$ for sufficiently large $n$. Therefore,
$O(1) \subset O(n) \subset O(n^2)$.

We can summarize the scales of some frequently used functions in terms of Big-O notation in the diagram below.

![](<../Source/8.4.1. Big-O Notation/Images/0934fb5b72015cacfb466a6f86f27bcd.png>)

Here, we have the following inclusions:

$$
O(1) \subset O(\log(n)) \subset O(n) \subset O(n\log(n)) \subset O(n^k) \subset O(a^n) \subset O(n!)
$$

Furthermore, $O(n^k) \subset O(n^{k+1})$ for all

$$
k=1,2,3,\ldots
$$

and $O(a^n) \subset O(b^n)$ whenever $a < b$. Notice that all inclusions are proper.

We also have the following two facts:

- If $c$ is any constant, then
$O(c g(n)) = O(g(n))$.
- If $O(g(n)) \subset O(f(n))$, i.e., $f(n)$ grow faster than $g(n)$, then
$O(g(n)+f(n)) = O(f(n))$.

<a id="a-worked-example"></a>
## A Worked Example

Let's prove that

$$
O(3n^5 + 2 +n!)= O(n!)
$$

Since $O(2) \subset O(3n^5)$, we can re-write the upper bound as follows:

$$
\begin{aligned}
O(3n^{5} + 2 + n!) &= O(3n^{5} + n!)
\end{aligned}
$$

Next, since

$$
O(3n^5)=O(n^5)
$$

we get the following:

$$
\begin{aligned}
O(3n^{5} + n!) &= O(n^{5} + n!)
\end{aligned}
$$

Finally, since $O(n^5) \subset O(n!)$, we obtain that

$$
O(n^5 + n!) = O(n!)
$$

<a id="using-the-properties-of-big-o-notation"></a>
## Using the Properties of Big-O Notation

**Example:** Simplify the asymptotic notation $O\left(3^n + 8 +2n^4\right)$.

**Explanation**

We can summarize the scales of some frequently used functions in terms of Big-O notation in the diagram below.

![](<../Source/8.4.1. Big-O Notation/Images/bfc39a209bd0ce7d5341aa1148954ed1.png>)

Here, we have the following inclusions:

$$
O(1) \subset O(\log(n)) \subset O(n) \subset O(n\log(n)) \subset O(n^k) \subset O(a^n) \subset O(n!)
$$

Furthermore, $O(n^k) \subset O(n^{k+1})$ for all

$$
k=1,2,3,\ldots
$$

and $O(a^n) \subset O(b^n)$ whenever $a < b$. Notice that all inclusions are proper.

Also,

$$
O(c g(n)) = O(g(n))
$$

for any constant multiplier $c$, and if $O(g(n)) \subset O(f(n))$, then

$$
O(g(n)+f(n)) = O(f(n))
$$

Now, since $O(8) \subset O(2n^4)$, we can re-write the upper bound as follows:

$$
\begin{aligned}
O(3^{n} + 8 + 2n^{4}) &= O(3^{n} + 2n^{4})
\end{aligned}
$$

Next, since

$$
O(2n^4)=O(n^4)
$$

we get the following:

$$
\begin{aligned}
O(3^{n} + 2n^{4}) &= O(3^{n} + n^{4})
\end{aligned}
$$

Finally, since $O(n^4) \subset O(3^n)$, we obtain that

$$
O(3^n + n^4) = O(3^n)
$$

Therefore, we have

$$
O\left(3^n + 8 +2n^4\right) = O(3^n)
$$
